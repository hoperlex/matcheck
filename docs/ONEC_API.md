# MatCheck → 1С: выгрузка приёмок материалов

Описание HTTP API для разработчиков 1С. Редакция от 11.11.2026.

Портал MatCheck отдаёт 1С приёмки материалов, подтверждённые на объектах. По каждой приёмке передаются:
- номер приёмки, объект, поставщик, получатель (подрядчик), договор с GUID 1С;
- документы приёмки (УПД, ТОРГ-12, накладные) с номером, датой и ИНН сторон;
- строки: номенклатура, количество, цены без НДС и с НДС, ставка, суммы, НДС;
- итоги;
- XML УПД из ЭДО — если к приёмке привязана электронная УПД.

1С сама забирает приёмки по расписанию и подтверждает загрузку. По подтверждению портал знает, что приёмка «выкачана».

---

## 1. Как устроен обмен

Инициатор всегда 1С: портал никуда не звонит. Обмен ведёт **одно регламентное задание**. Его цикл, например раз в 15–30 минут:

1. **Получить токен** по client_id и секрету (раздел 2).
2. **Получить очередь** — список приёмок, которые нужно загрузить, обновить или удалить в 1С (раздел 3).
3. **Забрать данные** приёмок пачками до 50 штук (раздел 4).
4. **Записать в 1С** каждую приёмку одной транзакцией (раздел 5).
5. **Подтвердить** порталу, какую версию приёмки 1С сохранила (раздел 7).

Портал запоминает, что именно подтвердила 1С. Если после этого приёмку исправят в портале (цену, количество, документ), она снова попадёт в очередь как изменённая. Если её удалят — как удалённая.

Важно:
- **Параллельно одну приёмку не обрабатывать.** Регламентное задание не должно запускаться вторым экземпляром, пока работает первый.
- **Подтверждать только после записи в 1С**, то есть после фиксации транзакции.
- Повторная обработка и повторное подтверждение безопасны: результат будет тот же.

## 2. Подключение

| | |
|---|---|
| Адрес | `https://mat.su10.ru` |
| Протокол | HTTPS, порт 443 |
| Формат | JSON в кодировке UTF-8; заголовок `Content-Type: application/json` |
| Учётные данные | `client_id` и секрет — выдаёт администратор портала |

Секрет показывается один раз. Храните его в защищённом хранилище 1С, например в `БезопасноеХранилищеДанных`. В портале секрет хранится только в виде хеша: потерянный секрет восстановить нельзя, можно только выпустить новый.

Портал может разрешить доступ только с определённых адресов. Сообщите администратору портала внешний IP-адрес сервера 1С.

### Получение токена

```
POST /api/v1/public/integration/token
Content-Type: application/json

{
  "grant_type": "client_credentials",
  "client_id": "onec",
  "client_secret": "mcs_…"
}
```

Тело запроса — только JSON, форма `application/x-www-form-urlencoded` не принимается.

Ответ `200`:

```json
{
  "access_token": "eyJhbGciOiJFZERTQSIsInR5cCI6Im1jK2p3dCJ9…",
  "token_type": "Bearer",
  "expires_in": 600,
  "scope": "onec.deliveries:read onec.deliveries:ack"
}
```

- Токен действует **10 минут** (`expires_in` — в секундах). Берите новый в начале каждого цикла и при любом ответе `401`.
- Во все остальные запросы токен передаётся заголовком `Authorization: Bearer <access_token>`. В адресной строке и в cookie токен не принимается.
- Права учётки:
  - `onec.deliveries:read` — читать очередь и данные;
  - `onec.deliveries:ack` — подтверждать загрузку.

| Ответ | Причина |
|---|---|
| `401 {"error":"invalid_client"}` | Неверный client_id или секрет, учётка отозвана или запрос не из разрешённой сети. Причину портал не уточняет |
| `429` | Слишком частые запросы токена. Подождите столько секунд, сколько указано в заголовке `Retry-After` |
| `503 {"error":"integration_disabled"}` | Выгрузка в 1С выключена на стороне портала |

Если учётку отзовут или выпустят новый секрет, все выданные ранее токены перестанут действовать сразу.

## 3. Очередь

```
GET /api/v1/integration/1c/deliveries/queue?limit=100
Authorization: Bearer <токен>
```

| Параметр | Обязателен | Что значит |
|---|---|---|
| `limit` | нет | Сколько элементов на странице: от 1 до 500. По умолчанию 100 |
| `cursor` | нет | Продолжение обхода: значение `nextCursor` с предыдущей страницы |
| `confirmedBefore` | нет | Только для новых приёмок: брать подтверждённые МОЛ раньше этого момента. Формат ISO-8601 с часовым поясом, например `2026-11-12T09:00:00+03:00` |

Ответ:

```json
{
  "items": [
    {
      "id": "0b6c1f4e-6a2d-4f3b-9a51-2c7e8d9f0a11",
      "displayId": 24508,
      "reason": "new",
      "sortAt": "2026-11-12T08:01:02.123456Z",
      "exportedHash": null,
      "detectedHash": null,
      "lastError": null
    }
  ],
  "nextCursor": "WyIyMDI2LTExLTEyVDA4OjAxOjAyLjEyMzQ1NloiLCIwYjZjMWY0ZS0uLi4iXQ",
  "truncated": true,
  "generatedAt": "2026-11-12T08:15:00.000Z"
}
```

| Поле | Что это |
|---|---|
| `id` | Идентификатор приёмки (uuid) — ключ для 1С |
| `displayId` | Номер приёмки, который видят пользователи портала |
| `reason` | Что сделать в 1С — см. таблицу ниже |
| `sortAt` | Время появления причины; по нему (и по `id`) упорядочена очередь |
| `exportedHash` | Хеш версии, которую 1С подтвердила последней. `null` — ещё не подтверждала |
| `detectedHash` | Для `changed` — хеш текущей версии в портале |
| `lastError` | Текст последней ошибки, о которой сообщила 1С (раздел 7) |
| `nextCursor` | Курсор следующей страницы; `null` — страниц больше нет |
| `truncated` | `true` — есть следующая страница |

**Причины (`reason`)**

| `reason` | Что случилось | Что сделать в 1С |
|---|---|---|
| `new` | Приёмку подтвердил МОЛ, 1С её ещё не загружала | Забрать данные и создать документы |
| `changed` | Приёмку изменили в портале после загрузки в 1С | Забрать данные и **заменить** документы целиком |
| `deleted` | Приёмку удалили в портале | Пометить на удаление все документы 1С этой приёмки. Данные забирать не нужно |
| `restored` | Удалённую приёмку восстановили | Как `new`: забрать данные и создать (восстановить) документы |

**Правила очереди**
- У приёмки в очереди всегда одна причина. Если подходят несколько, берётся старшая: `deleted` → `restored` → `changed` → `new`.
- Обходите очередь **с начала до конца**: первая страница без `cursor`, дальше — с `cursor`, пока `nextCursor` не станет `null`.
- **Каждый цикл начинайте с первой страницы.** Пока вы идёте по страницам, приёмку могут изменить, и в этом цикле она может прийти дважды или не прийти вовсе. Повторная обработка безопасна, а пропущенная приёмка придёт в следующем цикле.
- Если приёмку не удалось загрузить (например, нет номенклатуры), сообщите об ошибке (раздел 7) и идите дальше. Приёмка останется в очереди и придёт в следующем цикле, но обход не остановит.
- Приёмка уходит из очереди, когда 1С подтвердит текущую версию.

**Что попадает в очередь**
- Приёмки в статусе «Подтверждено МОЛ», подтверждённые после даты начала выгрузки. Дату задаёт портал: более ранние приёмки в очередь не попадают, но любую можно запросить по номеру.
- Перемещения между объектами в очередь **не попадают**: это внутреннее движение, а не закупка. По номеру их тоже можно запросить, у них `operation = "transfer"`.
- Изменения портал отслеживает **30 дней** после того, как 1С загрузила приёмку. Изменение, найденное в этот срок, остаётся в очереди, пока 1С его не подтвердит.
- Удаление и восстановление отслеживаются без срока.

Около 10% приёмок исправляют позже чем через час после подтверждения МОЛ. Если 1С удобнее не брать совсем свежие приёмки, передавайте `confirmedBefore` = «сейчас минус 1–2 часа». Это только уменьшит число повторных загрузок; изменения всё равно придут как `changed`.

## 4. Данные приёмки

### Запросы

```
GET /api/v1/integration/1c/deliveries?ids=<id>,<id>,…        — пачка, до 50 id через запятую
GET /api/v1/integration/1c/deliveries/<id>                    — одна приёмка
GET /api/v1/integration/1c/deliveries/by-number/<displayId>   — одна приёмка по номеру
```

Ответ пачки:

```json
{
  "snapshotAt": "2026-11-12T08:15:01.204513Z",
  "items": [ { …приёмка… } ],
  "missing": [ { "id": "…", "state": "deleted" } ]
}
```

- `missing` — запрошенные приёмки, которых в портале нет: `deleted` — удалена, `not_found` — не существовала.
- Одиночный запрос по такой приёмке отвечает `404` с `{"error":"deleted"}` или `{"error":"not_found"}`.

### Структура приёмки

```
Приёмка
├─ шапка: номер, объект, признак, поставщик, получатель, договор
├─ edo[]        — УПД из ЭДО, привязанные к приёмке целиком
├─ groups[]     — группы строк
│   ├─ group "doc:<id документа>"  — документ (УПД/ТОРГ-12/накладная) + его строки + итоги
│   ├─ …
│   └─ group "nodoc"               — строки без документа + итоги
└─ totals       — итоги по всей приёмке
```

### Форматы значений

| Что | Формат | Пример |
|---|---|---|
| Деньги | Строка, точка как разделитель, 2 знака | `"1234.50"` |
| Цена | Строка, до 4 знаков | `"1234.5600"` |
| Количество | Строка, до 4 знаков | `"2.5000"` |
| Ставка НДС | Строка, проценты | `"20.00"` |
| Дата и время | ISO-8601, UTC | `"2026-11-12T08:01:02.123456Z"` |
| Дата документа и договора | `ГГГГ-ММ-ДД` | `"2026-11-10"` |
| Идентификаторы | uuid строкой | `"0b6c1f4e-…"` |
| Нет значения | `null` (в 1С — `Неопределено`) | |

Деньги и количества передаются строками, чтобы не терять точность. В 1С строку переводите функцией `Число()`: она понимает точку как разделитель.

### Шапка приёмки

| Поле | Что это |
|---|---|
| `id` | Идентификатор приёмки — **ключ для 1С** |
| `displayId` | Номер приёмки в портале |
| `status` | Статус приёмки. В очереди всегда `confirmed_mol` («Подтверждено МОЛ»). По номеру можно получить и другие: `not_filled`, `draft`, `filled` |
| `confirmedAt` | Когда МОЛ подтвердил приёмку |
| `arrivedAt` | Когда машина прибыла на объект |
| `snapshotAt` | Когда портал прочитал данные — только для справки |
| `deletion` | `{"pendingSince": …}`, если приёмка лежит в корзине портала; иначе `null` |
| `operation` | `supply` — поставка от поставщика; `transfer` — перемещение между объектами |
| `sourceShipmentDisplayId` | Для перемещения — номер отгрузки, из которой оно пришло |
| `site` | Объект: `code` (код), `name` (название), `fotSiteId` (код объекта в системе ФОТ) |
| `purpose` | Признак приёмки — см. таблицу ниже |
| `supplier` | Поставщик, указанный в шапке приёмки. Заполняется редко — поставщика берите из документа |
| `recipient` | Получатель, указанный в портале — см. ниже |
| `contract` | Договор 1С приёмки (общий) |
| `edo` | УПД из ЭДО, привязанные к приёмке целиком, а не к конкретному документу |
| `groups` | Группы строк — каждая станет отдельным документом 1С |
| `totals` | Итоги по всем строкам приёмки |
| `contentHash`, `hashVersion` | Отпечаток этой версии приёмки — передаётся в подтверждение |
| `export` | Что портал знает о загрузке в 1С — см. ниже |

**Признак приёмки (`purpose`)**

| Значение | В портале |
|---|---|
| `own_forces` | Свои силы |
| `realization` | Реализация |
| `tolling_act` | Давальческий акт |
| `contractor_materials` | Материалы подрядчика |
| `realization_tolling` | Реализация + давальческий |
| `null` | Не указан |

**Получатель (`recipient`)**

| `kind` | Что значит | Заполненные поля |
|---|---|---|
| `contractor` | Подрядчик | `inn`, `kpp`, `name` |
| `mol` | Своя бригада, материально ответственное лицо | `name` (ФИО), `molId` |
| `none` | Получатель в портале не указан | — |

**Договор (`contract`)**: `onecId` — GUID договора в 1С, `counterpartyOnecId` — GUID контрагента в 1С, `number`, `date`, `name`. Договоры загружены в портал из 1С, поэтому GUID те же, что у вас.

**Состояние загрузки (`export`)**

| Поле | Что это |
|---|---|
| `state` | `not_exported` — 1С ещё не подтверждала; `exported` — у 1С текущая версия; `changed` — у 1С другая версия; `deleted` — 1С подтвердила удаление |
| `exportedAt` | Когда 1С подтвердила версию |
| `exportedHash` | Хеш подтверждённой версии |
| `queueReason` | Причина, по которой приёмка сейчас в очереди, если она там |
| `lastError`, `lastErrorAt` | Последняя ошибка загрузки, о которой сообщила 1С |

### Группа

| Поле | Что это |
|---|---|
| `groupKey` | `doc:<id документа>` — строки документа; `nodoc` — строки без документа |
| `document` | Документ группы; у `nodoc` — `null` |
| `lines` | Строки группы. Список может быть пустым: документ привязан, а строк по нему нет |
| `totals` | Итоги группы |

### Документ

| Поле | Что это |
|---|---|
| `id` | Идентификатор документа в портале |
| `kind` | Вид: `upd` (УПД, ТОРГ-12), `transport_waybill` (транспортная накладная) и др. |
| `number`, `date` | Номер и дата документа |
| `linked` | `true` — документ привязан к приёмке. `false` — документ отвязали, но строки остались под ним |
| `supplier` | Поставщик — как в документе: `inn`, `kpp`, `name` |
| `buyer` | Покупатель — как в документе |
| `consignee` | Грузополучатель — как в документе |
| `recipient`, `purpose` | Получатель и признак **этого документа**. В портале у документа может быть свой получатель, иначе действует общий из шапки |
| `contract` | Договор документа: свой, а если своего нет — общий из шапки |
| `printedTotals` | `totalSum` (всего с НДС) и `vatSum` из шапки документа. Это итоги **всего** документа, а не части этой приёмки |
| `sharedWith` | Другие приёмки с этим же документом: `id`, `displayId` (одна УПД на несколько рейсов) |
| `dedupKey` | Поставщик + номер + дата — по этому ключу портал ищет дубли документов |
| `portalDuplicates` | Другие карточки портала с тем же `dedupKey` — возможные дубли. Портал их не склеивает |
| `edo` | УПД из ЭДО, привязанные к этому документу |

**Где взять ИНН подрядчика.** Источника два, их нужно различать:
- `recipient` — получатель, которого указали люди в портале. Сейчас заполнен редко.
- `buyer` и `consignee` — то, что напечатано в документе. Покупателем там часто стоит сама СУ-10.

### Строка

| Поле | Что это |
|---|---|
| `lineNo` | Номер строки |
| `name` | Номенклатура — текст из документа |
| `material` | Позиция справочника материалов портала: `id`, `code`, `name`. Заполнена примерно у 3% строк, поэтому сопоставляйте номенклатуру по `name` |
| `unit` | Единица измерения, как в портале (`шт`, `т`, `м²`, …) |
| `okei` | Код ОКЕИ единицы, если он есть в справочнике портала |
| `qty` | Количество, от которого посчитаны суммы: фактически принятое, а если его нет — по документу |
| `qtyPlanned` | Количество по документу |
| `qtyActual` | Количество, фактически принятое на объекте |
| `price` | Цена за единицу **без НДС**, как хранится в портале |
| `priceWithVat` | Цена за единицу с НДС. Только если в строке есть ставка |
| `vatRate`, `vatRateKind` | Ставка НДС и её вид — раздел 6 |
| `sumExVat` | Сумма без НДС |
| `vatSum` | Сумма НДС |
| `sumWithVat` | Сумма с НДС |
| `itemKind` | `material` — материал, `asset` — основное средство |
| `inventoryNumber`, `serialNumber` | Инвентарный и серийный номер (для основных средств) |
| `warnings` | Что не так со строкой — см. ниже |

**Предупреждения строки (`warnings`)**

| Значение | Что значит |
|---|---|
| `no_qty` | Нет количества |
| `no_price` | Нет цены |
| `no_vat_rate` | Ставка НДС не известна |
| `no_vat_sum` | Сумма НДС не известна |
| `vat_mismatch` | НДС строки расходится с «сумма × ставка» больше чем на max(1 ₽; 0,1% суммы). Значение не исправлено, это только сигнал |

### Итоги (`totals`)

| Поле | Что это |
|---|---|
| `linesTotal` | Всего строк |
| `linesWithSum` | Строк, у которых есть сумма без НДС |
| `linesWithVat` | Строк, у которых есть НДС |
| `linesComplete` | Строк, у которых есть сумма с НДС |
| `sumExVat`, `vatSum`, `sumWithVat` | Суммы по строкам, где это значение есть. `null` — нет ни у одной строки |

## 5. Как отражать приёмку в 1С

### Ключ документа 1С

**Один документ 1С = одна группа приёмки.** Ключ документа — пара:

> `id` приёмки + `groupKey` группы

Храните оба значения в реквизитах документа 1С (например, «ИД приёмки MatCheck» и «Ключ группы MatCheck»). По ним документ находится при обновлении и удалении.

Примеры:
- Приёмка с одной УПД — один документ 1С.
- Приёмка с двумя УПД — два документа 1С.
- Одна УПД приехала тремя машинами, то есть тремя приёмками. Получится три документа 1С с одним номером УПД, у каждого своя часть строк. Список соседних приёмок — в `document.sharedWith`.
- Строки без документа — отдельный документ 1С с ключом `nodoc`.

### Загрузка новой или изменённой приёмки

Для `new`, `changed` и `restored` — **одной транзакцией 1С на всю приёмку**:
1. Для каждой группы из ответа найти документ 1С по ключу. Если не найден — создать.
2. Заполнить шапку и **полностью заменить табличную часть** строками группы. У строк нет постоянного идентификатора: при каждом сохранении в портале они пересоздаются, поэтому обновлять строки по одной нельзя.
3. Документы 1С этой приёмки, чьих `groupKey` в ответе больше нет (документ отвязали в портале), пометить на удаление.
4. Документы **других** приёмок не трогать.
5. Зафиксировать транзакцию и подтвердить загрузку хешем `contentHash` (раздел 7).

### Удаление

Для `deleted` пометить на удаление все документы 1С с этим `id` приёмки. Данные забирать не нужно. Затем подтвердить удаление (раздел 7).

Если приёмку потом восстановят, она придёт как `restored` — документы нужно восстановить или создать заново.

### Уже проведённые документы

Что делать, если приходит `changed` или `deleted` по проведённому документу или по закрытому периоду (перепровести, сторнировать, отложить до ручного разбора), решает 1С. Это пункт согласования (раздел 11).

### Счёт-фактура и общая УПД

Номер документа сам по себе не уникален. Портал гарантирует следующее:
- Одинаковый `document.id` в разных приёмках — это **один и тот же** документ портала (общая УПД на несколько рейсов).
- `dedupKey` (поставщик + номер + дата) и `portalDuplicates` подсказывают возможные дубли — разные карточки одного и того же документа. Портал их не склеивает.
- Номер исправления известен только у УПД из ЭДО: `edo[].correctionNumber`. У бумажных документов его нет.
- `printedTotals` — итоги всего документа. Сумма частей по нескольким приёмкам может с ними не совпасть: на объекте могли принять не всё.

Как регистрировать счёт-фактуру по общей УПД, решает 1С (раздел 11).

### Порядок версий

Порядок версий обеспечивает последовательная обработка: приёмка проходит путь «получить → записать → подтвердить» до конца, прежде чем её запросят снова. Поле `snapshotAt` — только для справки, упорядочивать по нему нельзя.

Если 1С применила `deleted` по устаревшей странице очереди, а приёмку к этому времени уже восстановили, в следующем цикле она придёт как `restored`.

## 6. Суммы, цены и НДС

**Опора — суммы, а не цены.** Заполняйте в 1С «Сумма», «Сумма НДС» и «Всего» значениями из ответа и **не пересчитывайте их из цены**:

| Поле | Как получено |
|---|---|
| `sumExVat` | `qty × price`, округлено до копеек по правилам математики |
| `vatSum` | НДС строки, как он записан в портале. Часто взят из документа поставщика и может отличаться от «сумма × ставка» на копейки (поставщик считает от неокруглённой цены) |
| `sumWithVat` | `sumExVat + vatSum`, только если известны оба |
| `priceWithVat` | `price × (100 + ставка) / 100`, 4 знака. Справочно |

Если 1С пересчитает сумму из цены, результат может разойтись с документом поставщика на копейки.

**Вид ставки НДС (`vatRateKind`)**

В 1С «0%» и «Без НДС» — разные ставки. В данных портала их различить нельзя, поэтому портал прямо говорит, что известно:

| `vatRateKind` | `vatRate` | Что значит |
|---|---|---|
| `percent` | `"20.00"`, `"10.00"`, … | Ставка известна |
| `zero_or_exempt` | `"0.00"` | Ставка 0: это **либо** «0%», **либо** «Без НДС». НДС строки = `"0.00"` |
| `unknown` | `null` | Ставки нет: в документе было «Без НДС» **или** ставку не удалось распознать |

Как поступать с `zero_or_exempt` и `unknown`, нужно согласовать (раздел 11). Ставку из XML ЭДО портал в строки не подставляет: строки приёмки и строки XML не сопоставлены — приёмка может быть частью УПД, названия в документе повторяются.

**Неполные приёмки приходят как есть.** Примерно у половины приёмок нет документа, примерно у двух третей нет цен. Отсутствующее значение — это `null`, а не ноль. Смотрите `warnings` строк и `totals.complete`.

## 7. Подтверждение загрузки

```
POST /api/v1/integration/1c/deliveries/ack
Authorization: Bearer <токен>
Content-Type: application/json

{
  "items": [
    { "id": "0b6c1f4e-6a2d-4f3b-9a51-2c7e8d9f0a11", "contentHash": "9c4e2a…f6a", "hashVersion": 1 },
    { "id": "1a2b3c4d-…", "deleted": true },
    { "id": "5e6f7a8b-…", "failed": { "message": "Не найдена номенклатура «Сетка сварная 100×100»" } }
  ]
}
```

В одном запросе — до 500 элементов. Каждый элемент — один из трёх видов:

| Вид | Когда отправлять |
|---|---|
| `contentHash` + `hashVersion` | Приёмка записана в 1С. Хеш и версию берите **из загруженных данных** (`contentHash`, `hashVersion`) — это отпечаток именно той версии, которую вы сохранили |
| `deleted: true` | Документы приёмки помечены на удаление |
| `failed` + `message` | Записать не удалось. Текст увидят в портале (до 2000 символов). Приёмка останется в очереди |

Ответ всегда `200`, результат — по каждому элементу:

```json
{ "results": [
  { "id": "0b6c1f4e-6a2d-4f3b-9a51-2c7e8d9f0a11", "result": "ok" },
  { "id": "1a2b3c4d-…", "result": "ok" },
  { "id": "5e6f7a8b-…", "result": "ok" }
] }
```

| `result` | Что значит |
|---|---|
| `ok` | Принято |
| `unknown_delivery` | Такой приёмки в портале никогда не было |
| `invalid_hash` | Хеш не той формы (должно быть 64 шестнадцатеричных символа) |
| `unsupported_hash_version` | Портал не знает такую версию хеша |

Правила:
- Подтверждать **только после фиксации транзакции 1С**.
- Подтверждение — это сообщение порталу «у 1С сейчас лежит вот эта версия». Портал принимает его всегда, а затем сам сравнивает со своей текущей версией. Если приёмку изменили, пока 1С её загружала, она вернётся в очередь как `changed`. Ничего дополнительно отслеживать не нужно.
- Повторно отправить то же подтверждение безопасно.

## 8. XML УПД из ЭДО

Если к приёмке привязана электронная УПД, у неё есть `xmlPath`:

```
GET /api/v1/integration/1c/deliveries/<id приёмки>/edo/<matchId>/xml
Authorization: Bearer <токен>
```

Ответ `200` — файл УПД **как его прислал оператор ЭДО**, без перекодировки. Заголовки ответа:

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/xml; charset=<кодировка из файла>`, обычно `windows-1251` |
| `Content-Disposition` | `attachment; filename*=UTF-8''<имя файла>` |
| `X-Content-SHA256` | sha256 полученных байтов — для проверки целостности |

Читайте тело как двоичные данные (`ПолучитьТелоКакДвоичныеДанные()`), а не как строку: иначе кириллица в `windows-1251` испортится. Файл подходит для стандартной загрузки УПД в 1С.

| Ответ | Причина |
|---|---|
| `404` | Привязки нет, она относится к другой приёмке или у привязанной УПД нет файла в реестре ЭДО портала |
| `413` | Файл больше допустимого размера |
| `503` + `Retry-After` | Хранилище временно недоступно — повторите позже |

Электронная УПД есть не у всех приёмок: только там, где менеджер вручную привязал её в портале. Сейчас это около 1% приёмок.

## 9. Ошибки и повторы

| Код | Что делать |
|---|---|
| `400` | Ошибка в запросе: неверные `ids` (`invalid_ids`), битый курсор (`invalid_cursor`), тело не по формату. Исправить запрос |
| `401` | Токен истёк или недействителен — получить новый и повторить. Повторный `401` при новом токене — учётку отозвали или запрос не из разрешённой сети |
| `403 insufficient_scope` | У учётки нет нужного права (например, только чтение без подтверждения) |
| `404` | Нет приёмки или файла |
| `429` | Слишком много запросов. Подождите `Retry-After` секунд. Лимиты: очередь — 30 запросов в минуту, остальное — 120 в минуту |
| `503 integration_disabled` | Выгрузка выключена в портале — повторить в следующем цикле |
| `503 not_configured` | В портале не задана дата начала выгрузки — обратиться к администратору портала |
| `503 storage_failed` | Хранилище файлов недоступно — повторить позже |
| `5xx` прочие | Сбой портала — повторить в следующем цикле |

## 10. Пример на встроенном языке 1С

Набросок цикла обмена, а не готовая обработка. Как именно создавать документы (`ЗаписатьПриёмку`, `ПометитьПриёмкуНаУдаление`), решаете вы.

```bsl
Перем Соединение, Токен, ИдКлиента, Секрет;

Процедура ВыполнитьОбмен() Экспорт
	// ИдКлиента и Секрет — из БезопасноеХранилищеДанных.
	Соединение = Новый HTTPСоединение("mat.su10.ru", 443, , , , 60, Новый ЗащищенноеСоединениеOpenSSL);
	Токен = ПолучитьТокен();

	Курсор = Неопределено;
	Пока Истина Цикл
		Адрес = "/api/v1/integration/1c/deliveries/queue?limit=200";
		Если Курсор <> Неопределено Тогда
			Адрес = Адрес + "&cursor=" + Курсор;
		КонецЕсли;
		Страница = ВыполнитьЗапрос("GET", Адрес);
		ОбработатьСтраницу(Страница["items"]);
		Курсор = Страница["nextCursor"];
		Если Курсор = Неопределено Тогда
			Прервать;
		КонецЕсли;
	КонецЦикла;
КонецПроцедуры

Процедура ОбработатьСтраницу(Элементы)
	Подтверждения = Новый Массив;
	КЗагрузке = Новый Массив;

	Для Каждого Элемент Из Элементы Цикл
		Если Элемент["reason"] = "deleted" Тогда
			ПометитьПриёмкуНаУдаление(Элемент["id"]); // все документы 1С с этим ИД приёмки
			Подтверждения.Добавить(Новый Структура("id, deleted", Элемент["id"], Истина));
		Иначе
			КЗагрузке.Добавить(Элемент["id"]); // new, changed, restored
		КонецЕсли;
	КонецЦикла;

	// Пачки по 50.
	Индекс = 0;
	Пока Индекс < КЗагрузке.Количество() Цикл
		Пачка = Новый Массив;
		Пока Индекс < КЗагрузке.Количество() И Пачка.Количество() < 50 Цикл
			Пачка.Добавить(КЗагрузке[Индекс]);
			Индекс = Индекс + 1;
		КонецЦикла;
		Ответ = ВыполнитьЗапрос("GET", "/api/v1/integration/1c/deliveries?ids=" + СтрСоединить(Пачка, ","));

		Для Каждого Приёмка Из Ответ["items"] Цикл
			НачатьТранзакцию();
			Попытка
				ЗаписатьПриёмку(Приёмка); // группы → документы по ключу (id приёмки + groupKey)
				ЗафиксироватьТранзакцию();
				Подтверждения.Добавить(Новый Структура("id, contentHash, hashVersion",
					Приёмка["id"], Приёмка["contentHash"], Приёмка["hashVersion"]));
			Исключение
				ОтменитьТранзакцию();
				Подтверждения.Добавить(Новый Структура("id, failed", Приёмка["id"],
					Новый Структура("message", Лев(КраткоеПредставлениеОшибки(ИнформацияОбОшибке()), 2000))));
			КонецПопытки;
		КонецЦикла;

		Для Каждого Отсутствующая Из Ответ["missing"] Цикл
			Если Отсутствующая["state"] = "deleted" Тогда
				ПометитьПриёмкуНаУдаление(Отсутствующая["id"]);
				Подтверждения.Добавить(Новый Структура("id, deleted", Отсутствующая["id"], Истина));
			КонецЕсли;
		КонецЦикла;
	КонецЦикла;

	Если Подтверждения.Количество() > 0 Тогда
		ВыполнитьЗапрос("POST", "/api/v1/integration/1c/deliveries/ack",
			Новый Структура("items", Подтверждения));
	КонецЕсли;
КонецПроцедуры

Функция ПолучитьТокен()
	Запрос = Новый HTTPЗапрос("/api/v1/public/integration/token");
	Запрос.Заголовки.Вставить("Content-Type", "application/json");
	Тело = Новый Структура("grant_type, client_id, client_secret", "client_credentials", ИдКлиента, Секрет);
	Запрос.УстановитьТелоИзСтроки(ВJSON(Тело), КодировкаТекста.UTF8, ИспользованиеByteOrderMark.НеИспользовать);
	Ответ = Соединение.ОтправитьДляОбработки(Запрос);
	Если Ответ.КодСостояния <> 200 Тогда
		ВызватьИсключение "MatCheck: токен не получен, код " + Ответ.КодСостояния;
	КонецЕсли;
	Возврат ИзJSON(Ответ.ПолучитьТелоКакСтроку(КодировкаТекста.UTF8))["access_token"];
КонецФункции

// Запрос с токеном; при 401 — один повтор с новым токеном.
Функция ВыполнитьЗапрос(Метод, Адрес, Тело = Неопределено, Повтор = Ложь)
	Запрос = Новый HTTPЗапрос(Адрес);
	Запрос.Заголовки.Вставить("Authorization", "Bearer " + Токен);
	Если Тело <> Неопределено Тогда
		Запрос.Заголовки.Вставить("Content-Type", "application/json");
		Запрос.УстановитьТелоИзСтроки(ВJSON(Тело), КодировкаТекста.UTF8, ИспользованиеByteOrderMark.НеИспользовать);
	КонецЕсли;
	Ответ = Соединение.ВызватьHTTPМетод(Метод, Запрос);
	Если Ответ.КодСостояния = 401 И НЕ Повтор Тогда
		Токен = ПолучитьТокен();
		Возврат ВыполнитьЗапрос(Метод, Адрес, Тело, Истина);
	КонецЕсли;
	Если Ответ.КодСостояния <> 200 Тогда
		ВызватьИсключение "MatCheck: " + Метод + " " + Адрес + " — код " + Ответ.КодСостояния;
	КонецЕсли;
	Возврат ИзJSON(Ответ.ПолучитьТелоКакСтроку(КодировкаТекста.UTF8));
КонецФункции

Функция ВJSON(Значение)
	Запись = Новый ЗаписьJSON;
	Запись.УстановитьСтроку();
	ЗаписатьJSON(Запись, Значение);
	Возврат Запись.Закрыть();
КонецФункции

Функция ИзJSON(Строка)
	Чтение = Новый ЧтениеJSON;
	Чтение.УстановитьСтроку(Строка);
	Результат = ПрочитатьJSON(Чтение, Истина); // Истина — объекты читаются в Соответствие
	Чтение.Закрыть();
	Возврат Результат;
КонецФункции
```

Пояснения к примеру:
- `ПрочитатьJSON(Чтение, Истина)` возвращает `Соответствие`: поля читаются как `Приёмка["contentHash"]`, а `null` становится `Неопределено`.
- Деньги и количества в ответе — строки: `Число(Строка["sumExVat"])`. Перед преобразованием проверяйте на `Неопределено`.
- XML УПД читайте через `Ответ.ПолучитьТелоКакДвоичныеДанные()`.

## 11. Что согласовать до запуска

1. **Вид документа 1С** для группы приёмки и реквизиты для ключа (`id` приёмки + `groupKey`).
2. **Счёт-фактура по общей УПД** (одна УПД на несколько приёмок) и исправленные УПД: как регистрировать, чтобы не задвоить.
3. **Проведённые документы и закрытый период** при `changed` и `deleted`: перепроводить, сторнировать или ставить на ручной разбор.
4. **Неполные приёмки** — без документа, без цен, без ставки: загружать как есть, загружать в черновик или откладывать (`failed` с пояснением).
5. **Ставки `zero_or_exempt` и `unknown`**: какую ставку 1С ставит в этих случаях; нужно ли 1С брать ставку из XML ЭДО.
6. **Сопоставление номенклатуры** по названию (`name`) и единиц (`unit`, `okei`).
7. **Расписание обмена** и внешний IP-адрес сервера 1С — для ограничения доступа на стороне портала.
8. **Канал для передачи** client_id и секрета.
